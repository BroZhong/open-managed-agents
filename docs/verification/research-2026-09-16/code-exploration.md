## Coordinator 抽查

事实：父 Turn 的 adapter `onResolved` 回调把真实解析配置写入 `delegationRun.effectiveConfig`（[session-router.ts](/home/user/workspace/research/source/open-managed-agents-738c128bf42628bfcc5201b1d17d784e29f034bd/server/packages/session-router/src/session-router.ts:1398)）；coordinator 禁止子调用覆盖 model，取该配置的 model 作为 `parentModel` 交给 store（[delegation-coordinator.ts](/home/user/workspace/research/source/open-managed-agents-738c128bf42628bfcc5201b1d17d784e29f034bd/server/packages/session-router/src/delegation-coordinator.ts:62)、[delegation-coordinator.ts](/home/user/workspace/research/source/open-managed-agents-738c128bf42628bfcc5201b1d17d784e29f034bd/server/packages/session-router/src/delegation-coordinator.ts:70)）；store 将其固化到 child agent 与 execution，并标记来源 `parent`（[delegation-store.ts](/home/user/workspace/research/source/open-managed-agents-738c128bf42628bfcc5201b1d17d784e29f034bd/server/packages/store/src/delegation-store.ts:122)、[delegation-store.ts](/home/user/workspace/research/source/open-managed-agents-738c128bf42628bfcc5201b1d17d784e29f034bd/server/packages/store/src/delegation-store.ts:130)）。固定分两步：accept 时持久化 execution model，新建 child 时同步写入 agent；child 真正启动前又从 execution 覆盖当前 agent model（[session-router.ts](/home/user/workspace/research/source/open-managed-agents-738c128bf42628bfcc5201b1d17d784e29f034bd/server/packages/session-router/src/session-router.ts:1080)。因而 resume 使用本次父 Turn 的解析结果，而非初建 child 的旧配置。测试在父配置被并发修改后，验证 create/resume 的 child model 仍等于各父 Turn 实际解析值（[delegation.test.ts](/home/user/workspace/research/source/open-managed-agents-738c128bf42628bfcc5201b1d17d784e29f034bd/server/packages/session-router/test/delegation.test.ts:47)）。

## 验证边界

事实：隔离测试使用 FakeRedis/内存 store，coordinator 测试使用 mock adapter/内存 store。推断：调用链能保证参数级隔离和 model 固定，但这些测试未覆盖真实 Redis 集群、PostgreSQL、多 Host 竞争及真实 provider adapter 是否准确触发 `onResolved` 的集成边界。
