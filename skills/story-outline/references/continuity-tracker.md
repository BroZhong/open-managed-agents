# 故事种子连续性自检清单

这份清单服务于故事架构师和金牌编辑，是 `outline-contract.md` 的连续性细则。
30 章跨度长，最容易出的不是单章质量问题，而是**章与章之间的矛盾**：时间线对不上、物品凭空出现或重复取得、角色死了功能却还在用、谁该知道什么乱套。

故事架构师分段共创（CH01-06 / CH07-18 / CH19-30）和交付前用它自检；金牌编辑审核时用它逐维核对。它是一份核对工具，不是要写进 `章节大纲.md` 的产物。

## 5 维状态追踪

分段共创时，每写完一段，先在心里（或临时草稿里）过一遍这五维当前的"存档状态"，再往下写：

1. **时间线与倒计时**
   - 当前推进到第几天 / 什么时段？是否与上一章严格连续？
   - 有没有在用的倒计时或截止点（如"三天后开庭"）？后续章节是否和它一致，没有自相矛盾的新倒计时？

2. **关键物品与证据**
   - 主角此刻持有哪些关键物品 / 证据 / 武器 / 线索？
   - 哪些在这一段里取得、丢失、被毁或转交了？取得过的东西，后面不许再"重新取得"一次。

3. **角色状态（生 / 死 / 伤 / 俘）**
   - 主要角色和对手此刻的身体与处境状态分别是什么？
   - 有谁在这一段里死亡、重伤、被俘或脱困？状态变化后，他/她还能不能继续承担原计划的剧情功能？

4. **信息不对称（谁知道什么）**
   - 这一段里哪些关键秘密被揭示了、揭示给了谁？
   - 哪些角色仍被蒙在鼓里？后续的张力很多时候就靠"观众知道、角色不知道"或"A 知道、B 不知道"撑着，别不小心提前让所有人都知道。

5. **未解线索与活跃钩子**
   - 上一段结尾留下的钩子 / 悬念 / 待回应的事，分别在哪一章兑现？
   - 有没有抛出去却再也没人管的线？要么后续回收，要么一开始就别埋。

## 跨章一致性硬检查

- **物品不重复取得**：同一件关键物品，取得动作只发生一次；之后默认主角持有它，不再写"再去拿一次"。
- **倒计时不打架**：全程维持一条清晰的线性时间线，不要出现互相矛盾的截止点。
- **死亡不断功能**（重点，来自实战教训）：给某个角色安排死亡 / 退场节点时，必须同步检查他/她原本承担的后续功能（助力、传递信息、制造变数、情感支点）会不会因此断线。如果会断，要么提前安排接替者，要么用"遗物 / 遗言 / 录音 / 第三方转述"等机制把功能接出去。
- **能力 / 设定一致**：人物能力、世界规则一旦设定，后续章节不能临时违反；需要补充设定时只能"新增"，不能悄悄改写已写定的设定。
- **关系变化有迹可循**：关系的拉近 / 破裂 / 反转，要有可追溯的事件支撑，不能跳跃式地突然变好或突然反目。

## 分段交接状态表（共创时的临时工具）

分段往后写之前，用下面这张表把上一段结尾的"存档"写清楚，确保下一段从一致的状态接上。这张表是过程工具，不写进 `章节大纲.md`：

```text
【截至第 X 章末的存档状态】
- 时间线：第 ? 天 / ? 时段；活跃倒计时：?
- 关键物品 / 证据：主角现持有 ?；本段新增 / 丢失：?
- 角色状态：?（生 / 死 / 伤 / 俘，逐个列）
- 信息不对称：谁刚知道了 ?；谁仍不知道 ?
- 未解线索 / 活跃钩子：本段结尾留下 ?，预计在第 ? 章兑现
```

## 交付前最后核对

整本 30 章定稿前，至少确认：

- 时间线从第 1 章到第 30 章连续、无矛盾倒计时。
- 没有重复取得的物品、没有断了功能的死亡、没有被遗弃的线索。
- 信息不对称的设计自洽：每个关键真相的"揭示时机 / 揭示对象"都说得通。
- 第 30 章把主外部冲突和主情感弧都收束掉，不靠续集悬念逃避收尾。
